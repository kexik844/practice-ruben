# Документация REST API — Каталог услуг

Базовый URL: `http://127.0.0.1:8000/api/`. Формат данных — JSON. Администратор — пользователь с `is_staff=True`. Для ручной проверки можно войти через `/api-auth/login/` (SessionAuthentication); для HTTP-клиента в локальной среде доступна BasicAuthentication DRF. При сессионных изменяющих запросах нужен CSRF-токен.

## Маршруты

| Метод | Маршрут | Доступ |
|---|---|---|
| GET | `/api/categories/` | Всем |
| GET | `/api/categories/{id}/` | Всем |
| POST | `/api/categories/` | Администратор |
| PUT/PATCH/DELETE | `/api/categories/{id}/` | Администратор |
| GET | `/api/categories/{id}/services/` | Всем, недоступные только администратору |
| GET | `/api/services/` | Всем, недоступные только администратору |
| GET | `/api/services/{id}/` | Всем, недоступные только администратору |
| POST | `/api/services/` | Администратор |
| PUT/PATCH/DELETE | `/api/services/{id}/` | Администратор |
| POST | `/api/requests/` | Всем |
| GET | `/api/requests/` | Администратор |
| GET | `/api/requests/{id}/` | Администратор |
| PUT/PATCH/DELETE | `/api/requests/{id}/` | Администратор |

## Пагинация и фильтры

Все списки используют `page` (положительное целое) и `page_size` (5–10, по умолчанию 5). Ответ: `count`, `next`, `previous`, `results`.

Для списка услуг и услуг категории:

| Параметр | Пример | Значение |
|---|---|---|
| category | `1` | ID существующей категории |
| is_available | `true` | `true` или `false` |
| min_price | `1000` | Неотрицательная минимальная цена |
| max_price | `5000` | Неотрицательная максимальная цена |
| search | `ремонт` | По названию и описанию |
| ordering | `price` | По возрастанию; `-price` по убыванию |

Составной запрос:

```http
GET /api/services/?category=1&is_available=true&min_price=1000&max_price=5000&ordering=price&page_size=5
GET /api/categories/1/services/?search=ремонт&ordering=-price
```

Ошибочные, повторяющиеся и неизвестные параметры списка возвращают 400; номер несуществующей страницы — 404. `min_price` не может превышать `max_price`. Гость с `is_available=false` получает пустой список. Сортировка при равной цене стабильна по ID. Услуги и их категории загружаются через `select_related('category')`.

## Примеры POST

Категория (slug генерируется на сервере):

```json
{"name": "Обслуживание"}
```

Услуга (ID категории заменить на существующий):

```json
{"category": 1, "name": "Диагностика", "description": "Проверка техники", "price": "500.00", "duration_minutes": 30, "is_available": true}
```

Заявка (указать будущую дату и существующую доступную услугу):

```json
{"service": 1, "client_name": "Тестовый клиент", "phone": "+70000000000", "desired_at": "2030-01-01T12:00:00+03:00"}
```

При создании заявки допустимо передать `service_id` вместо `service`. Если указаны оба поля, их значения должны совпадать. Сервер присваивает `status=new` независимо от входного значения. Телефон должен содержать 10–15 цифр, допустимы начальный плюс, пробелы, скобки и дефисы. Пустое имя, телефон, отсутствующая или недоступная услуга, прошедшая дата — 400. Статусы: `new`, `confirmed`, `completed`, `cancelled`.

Детальная информация об услуге дополнительно содержит `category_name`. `price` передаётся строкой в формате decimal, стоимость неотрицательна, продолжительность строго больше 0. `created_at` генерируется автоматически.

## Коды ответа

| Код | Смысл |
|---|---|
| 200 | Успешное чтение/изменение |
| 201 | Создание |
| 204 | Удаление |
| 400 | Ошибки данных или параметров |
| 401/403 | Нет прав |
| 404 | Объект или страница отсутствует/недоступна |
| 409 | Удаление связано с существующими записями |

Пример ошибки валидации: `{"service": ["Данная услуга недоступна."]}`. Удаление категории с услугами или услуги с заявками запрещено.
