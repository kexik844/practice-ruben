# Отчёт о проверке — задание №2

## Предыдущая проверка интерфейса

Восемь сценариев JSX-версии ранее прошли в браузере с имитацией API и адаптером маршрутов. Проверены синтаксис, отображение и взаимодействия с интерфейсом. Затем проведена отдельная успешная проверка с настоящим Django на чистой учебной базе: сборка Vite, серверные тесты и все восемь сценариев Playwright прошли.

| № | Сценарий | Тестовый API | Реальный API |
|---|---|---|---|
| 1 | Фильтры, поиск 400 мс и сортировка | Пройден | Пройден |
| 2 | Пагинация, избранное, 390 px | Пройден | Пройден |
| 3 | Карточка, обновление маршрута, 404 | Пройден | Пройден |
| 4 | Прошедшая дата, 400 рядом с полем | Пройден | Пройден |
| 5 | Создание заявки, номер из ответа | Пройден | Пройден |
| 6 | CRUD, категория, цена, доступность, удаление | Пройден | Пройден |
| 7 | Ошибка прав 403 и отказ входа | Пройден | Пройден |
| 8 | Ошибка 500, retry, пустая выдача | Пройден | Пройден |

При визуальной проверке использовались ширины 390 и 1280 px. Установка зависимостей в среде подготовки была ограничена сетью. Сведения о проверке задания №1 сохранены отдельно в [backend/TEST_RESULTS.md](../backend/TEST_RESULTS.md). Повторная проверка Django API также завершилась успешно.

## Воспроизводимая проверка

Тесты находятся в `frontend/tests/catalog.spec.js`. Для запуска требуется работающий Django, свежая база после `seed_catalog` и учётная запись администратора. Инструкция приведена в корневом README.

Сценарий 8 намеренно имитирует ответ 500 на запрос браузера, затем возвращает работу с реальным API. Остальные запросы при обычном запуске Playwright идут к Django. После успешного прохождения сценариев сохраняются скриншоты в `docs/screenshots/`. Пять снимков успешной проверки сохранены в [docs/screenshots](screenshots/).
