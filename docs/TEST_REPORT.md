# Отчёт о проверке — задание №2

## Предыдущая проверка интерфейса

Восемь сценариев JSX-версии ранее прошли в браузере с имитацией API и адаптером маршрутов. Проверены синтаксис, отображение и взаимодействия с интерфейсом. Это не подтверждает полноценную интеграцию с Django.

| № | Сценарий | Тестовый API | Реальный API |
|---|---|---|---|
| 1 | Фильтры, поиск 400 мс и сортировка | Пройден | Требуется запуск |
| 2 | Пагинация, избранное, 390 px | Пройден | Требуется запуск |
| 3 | Карточка, обновление маршрута, 404 | Пройден | Требуется запуск |
| 4 | Прошедшая дата, 400 рядом с полем | Пройден | Требуется запуск |
| 5 | Создание заявки, номер из ответа | Пройден | Требуется запуск |
| 6 | CRUD, категория, цена, доступность, удаление | Пройден | Требуется запуск |
| 7 | Ошибка прав 403 и отказ входа | Пройден | Требуется запуск |
| 8 | Ошибка 500, retry, пустая выдача | Пройден | Требуется запуск |

При визуальной проверке использовались ширины 390 и 1280 px. Установка зависимостей в среде подготовки была ограничена сетью. Сведения о вчерашних 18 API-тестах сохранены отдельно в [backend/TEST_RESULTS.md](../backend/TEST_RESULTS.md); они не являются результатом сегодняшнего запуска.

## Воспроизводимая проверка

Тесты находятся в `frontend/tests/catalog.spec.js`. Для запуска требуется работающий Django, свежая база после `seed_catalog` и учётная запись администратора. Инструкция приведена в корневом README.

Сценарий 8 намеренно имитирует ответ 500 на запрос браузера, затем возвращает работу с реальным API. Остальные запросы при обычном запуске Playwright идут к Django. После успешного прохождения сценариев сохраняются скриншоты в `docs/screenshots/`. GitHub Actions запускает проверку на отдельной базе и публикует снимки как артефакт; при успешном запуске в main добавляет их в репозиторий.

Результат текущего CI проверяйте на вкладке [Actions](https://github.com/kexik844/practice-ruben/actions).
